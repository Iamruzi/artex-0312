# 执行错误与跨意图恢复

这项改动减少宿主命令错误和无依据的重复续派，不改变任务授权范围、工具绑定、拦截策略、模型、费用预算或人工暂停状态。

## 当前行为

- 所有能执行本地命令的 Agent 都获得实际宿主 shell 说明。norma v0.4.3 在 Windows 使用 `powershell -NoProfile -NonInteractive -Command`，Unix 使用 `bash -c`；启动 ARTEX 的终端不决定工具解释器。远程会话的解释器仍由远端决定。
- Worker 首次遇到可识别的本地解析错误或命令缺失时，在下一次调用前收到环境纠偏；每种分类提前提醒一次，与已有停滞提醒共享每意图最多三次的上限。真正的同质无进展仍沿用原有 12/15 次判据与冷却机制。
- `graph_overview.recovery_memory` 汇总本任务最近最多 200 条工具错误，最多输出 20 组 `intent_id/tool/category/count/activity_id`。记录跨 Worker 和进程重启复用，来源是已有持久化活动表。计数只是采样窗口内的次数，不是整个任务的累计值。
- 分类包括 `shell_syntax`、`command_missing`、`policy_denied`、`tool_error`。这些是诊断提示，不是目标安全结论。概览只输出固定分类和记录引用，不复制可能含敏感信息的原始错误；完整输出仍按原有 trace 接口读取。
- 平台拒绝执行属于 `policy_denied`，提示要求遵守规则；不会把它当作目标 WAF，也不会自动改写、安装工具或放宽策略。

## 续派记录

规划者和主 Agent 在续派已结束的本任务意图时填写 `add_intent.recovery`。单条和 `intents` 批量入口均支持：

```json
{
  "summary": "用宿主原生读取器解析上次保存的本地测试结果",
  "recovery": {
    "previous_intent_id": 42,
    "reason": "shell_syntax",
    "change": "保留原请求文件，改用 PowerShell 原生读取并解析已保存的响应",
    "expected_signal": "成功解析一个 JSON 对象；若仍解析失败则记录本地错误并停止该尝试"
  }
}
```

`reason` 支持 `shell_syntax/command_missing/tool_error/budget/no_progress/policy_denied/new_evidence`。`change` 与 `expected_signal` 各需 8–600 字符；可选 `evidence_ids` 最多引用 8 个实际存在的本任务事实/发现，`new_evidence` 时必填。引用存在不表示事实已被独立验证，目标达成仍走既有证据判定。

数据库在同一事务中验证来源状态、任务归属、证据引用和恢复链重复：

- 来源只能是本任务 `done/blocked/exhausted` 意图。其他任务（包括关联任务）、仍在排队/运行或被人工停止/删除的意图不能作为恢复来源。
- 恢复链根节点与指纹由服务端计算，不采信调用者提供的值。
- 相同恢复链中，相同 `change`（忽略大小写与空白差异）且相同证据集合只允许一次；改变成功判据本身不能绕过重复检查。并发提交通过根节点行锁串行判定。
- 承接记录保存在节点 JSON 中，并随 open/running/recent-done 概览传给后续规划者与 Worker；不依赖进程内缓存，不需要新增数据库表。

为兼容旧客户端，全新意图或不含 `recovery` 的调用保留原行为；它不会语义识别所有换词重复。提示要求已知续派使用结构化记录，但模型仍可能不遵循，因此不能将这项改动描述为“从此不会重复”或“具备专家水平”。

## 验证（2026-10-24）

在仓库外的本机 PostgreSQL 实例中新建独立测试数据库，未对正在运行的靶场数据库执行测试：

- 测试任务隔离、合法/非法前序状态、多轮祖先重复、大小写/空白归一、证据引用、无孤儿节点、8 路并发仅一次入库。
- 测试错误摘要有界、原始输出不进入概览、工具入口端到端读写、旧客户端兼容、错误参数明确拒绝。
- 测试本地错误首次纠偏、Planner 指令优先、纠偏消费一次后恢复正常调用；回归既有停滞检测和 Agent 固定提示尾。
- `agent`、`db`、`intercept`、`guard` 包完整测试通过；另对 `server` 的相关用例定向验证。没有把未运行的完整 `server`/全仓测试报告为通过。
- 全仓 `go vet ./...`、`go build ./...` 和内嵌既有前端的 Windows 程序构建通过。
- 独立数据库、独立端口的程序启动检查：健康接口、初始化状态、前端首页均 200，测试登录和认证 API 可用，随后停止该测试进程。

这次没有改变运行中的任务或调用真实模型做新一轮靶场对照。代码测试和程序启动通过，不等于已经验证漏洞发现率或成本改善；需启用新程序后结合实际 trace 评估。
